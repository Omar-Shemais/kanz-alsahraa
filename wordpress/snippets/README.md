# إدارة تطبيق كنز كـCode Snippet

## كلمة مرور الحساب بعد تحقق الهاتف — 20 سبتمبر

الإصدار الحالي من الـSnippet هو `0.6.0` ودواله تبدأ بـ`kanz_v6_`. يضيف endpoint محمياً باسم `/wp-json/kanz/v1/account/password` تستخدمه نسخة التطبيق الجديدة بعد نجاح OTP وإنشاء الحساب. لا يقبل endpoint بريداً أو هاتفاً أو رقم مستخدم لاختيار الحساب؛ يلزم `User-Cookie` صالح صادر للحساب نفسه، ثم يدور cookie بعد `wp_set_password` حتى تظل جلسة التطبيق صالحة. توجد حدود للطول والمحاولات ولا تُحفظ كلمة المرور في إعدادات التطبيق أو السجلات.

حدّث الـSnippet أولاً ثم انشر بناء التطبيق الذي يحتوي حقلي كلمة المرور والتأكيد. الصق الملف دون أول سطر `<?php` واختر **Run everywhere**. لا تترك الإصدار `0.5.0` والإصدار `0.6.0` نشطين معاً؛ أسماء v6 تمنع خطأ إعادة التعريف أثناء فحص الاستبدال، لكنها ليست تصريحاً لتشغيل نسختين دائماً.

## تحديث فلتر المنتجات وتسجيل الهاتف — 19 سبتمبر

كان هذا التحديث في الإصدار `0.5.0`. أضيف قسم مستقل باسم «تصنيفات فلتر المنتجات» للتحكم في الظهور والترتيب داخل نافذة الفلترة، دون تغيير ترتيب صفحة التصنيفات أو بنية WooCommerce. يبقى «أحدث المنتجات» و«عروض اليوم الوطني» ظاهرين افتراضياً، بينما يُستبعد تصنيف WooCommerce الافتراضي «غير مصنف» عند إنشاء الإعداد لأول مرة.

يتطلب تطبيق إعداد `filterCategories` بناء نسخة التطبيق التي تحتوي هذا التحديث. حدّث الـSnippet الحالي من ملف `kanz-app-control-snippet.php` دون أول سطر PHP، ثم افتح اللوحة وراجع الاختيارات واضغط «نشر إعدادات التطبيق». لا تُفعّل نسختين من الـSnippet معاً.

## تحديث MStore والإشعارات من لوحة المسؤول — 18 سبتمبر

النسخة الحالية تقرأ config_ar.json مباشرة من مسار MStore الذي يحدده FlutterUtils (مع مسار uploads/flutter_config_files كبديل). عند فتح اللوحة لا يلزم استيراد متكرر. النشر يحفظ نسخة سابقة ثم يكتب الملف نفسه باستبدال ذري بعد فحص بصمة الملف. REST endpoint السابق يقرأ نفس الملف وليس مصدراً مستقلاً. لا تعدّل الملف من لوحة MStore وهذه اللوحة في الوقت نفسه، ولا تفترض أن CDN خارجياً قد أزال الكاش تلقائياً. لا تغيّر appConfig إذا كان يشير فعلاً إلى الملف نفسه. يلزم أن يملك PHP صلاحية الكتابة؛ إن لم يملكها تعرض اللوحة خطأ ولا تدعي نجاح النشر.

أضاف Antigravity نموذج إعداد Firebase من WordPress؛ تم تحصينه بتشفير AES-256-GCM بمفتاح مشتق من WordPress salts، دون autoload ودون إعادة عرض المفتاح. البيانات السابقة غير المشفرة تحتاج إعادة إدخال؛ يُحذف الخيار القديم بعد الحفظ الآمن. يلزم HTTPS ومفتاح Service Account لمشروع kanz-alsahra، وليس google-services.json. لا ترفعه للوسائط أو MStore ولا ترسله في المحادثة. حفظه مشفراً لا يحمي من اختراق WordPress بالكامل أو الوصول إلى قاعدة البيانات وsalts معاً؛ تغيير salts يتطلب إعادة الربط.

إرسال FCM HTTP v1 من خادم WordPress لا يحتاج Firebase Cloud Functions أو خطة Blaze. يحتاج صلاحيات Firebase المطلوبة واتصال HTTPS صادر من الاستضافة. النموذج يبدأ باختبار حساب واحد، ويستخدم user meta: mstore_device_token، ويرفض الحساب غير الموجود أو الرمز المفقود ولا يتحول إلى broadcast. المعيار هو رقم مستخدم WordPress، وليس Firebase UID. هذا مسار عروض عامة/اختبارات وليس قناة بيانات طلبات خاصة؛ الرمز المحفوظ قد يكون آخر جهاز أو قديماً، لذلك استخدم حساب اختبار تتحكم به وسجل دخولاً جديداً قبل الاختبار.

نسخة Flutter المحلية تضيف تسجيل الرمز عبر update_user_profile المصادق بcookie عند تسجيل الدخول، مستقلاً عن Firestore؛ يلزم إعادة بناء وتثبيت نسخة التطبيق ثم تسجيل الدخول بحساب الاختبار. لا ترسل إشعارات حقيقية للاختبار دون اختيار الحساب وتأكيد الجمهور. حالات accepted لا تثبت الوصول.

الفقرات القديمة أدناه تصف النسخة السابقة عند تعارضها مع هذا التحديث. نسخة plugin ZIP ليست طريقة النشر المعتمدة؛ حدّث الـSnippet الحالي لا تنشئ نسخة نشطة مكررة. تم اختبار الملفات والواجهات بمحاكاة محلية؛ لم نحدّث موقع الإنتاج أو نرسل إشعاراً من هذه الدفعة.

هذه هي صيغة النشر المطلوبة الآن بدلاً من إضافة ZIP مستقلة. تحتوي PHP والواجهة JavaScript في كود واحد؛ لا تحتاج رفع ملفات JS أو notifications.php منفصلة.

## ملف الاستيراد

`kanz-app-control.code-snippets.json` بصيغة Code Snippets، PHP scope = global / Run everywhere، وغير مفعل افتراضياً. من Snippets > Import اختر الملف ثم استورده **دون تفعيل تلقائي**. لا تدعم هذه الصيغة بالضرورة WPCode أو أي مدير snippets آخر.

## بديل اللصق

أنشئ PHP Snippet جديداً، والصق محتوى `kanz-app-control-snippet.php` **دون أول سطر <?php**. اختر Run everywhere وليس Admin only، لأن REST endpoint يجب أن يعمل خارج صفحات الإدارة. لا تستخدم Run once أو HTML snippet.

## قبل التفعيل على الإنتاج

- اختبر على WordPress معزول أولاً؛ lint/fحوص DOM لا تضمن التوافق مع كل إضافات الموقع.
- احتفظ بنسخة احتياطية قابلة للاسترجاع وطريقة تعطيل snippet إذا وقع خطأ. تعطيل snippet يوقف لوحة التحكم والرابط الخاص بها؛ التطبيق يحتفظ ببديل محلي/كاش، ولا يجب أن يعتمد الدخول والدفع على هذا الرابط.
- لا تفعل نسخة snippet ونسخة Kanz App Control plugin معاً. الحماية من التكرار موجودة، لكن اختر صيغة واحدة فقط.
- لم يتم تفعيل الكود أو تعديل الموقع الحي تلقائياً.

## الربط بعد الاختبار

1. يظهر في WordPress قسم «تطبيق كنز» للمسؤول ذي manage_options.
2. استورد ملف config_ar.json الجديد ذي 11 قسماً إلى اللوحة وراجع ثم انشره.
3. اللوحة تنشر `/wp-json/kanz/v1/config/ar` مستقلاً؛ لا تعدّل ملف MStore القديم تلقائياً.
4. لا تبدّل appConfig إلى رابط اللوحة قبل اختبار استجابته وبناء نسخة التطبيق التي تدعم التحكم. لم يتغير رابط التطبيق إلى endpoint غير المنشور.
5. بعد التحويل، استخدم اللوحة كمصدر وحيد ولا تعدّل ملف MStore الموازي وتنتظر أن يظهر في التطبيق.

## الإشعارات والتحديثات

- الإشعارات العامة لها نموذج إرسال وسجل محاولات، لكن الإرسال يبقى معطلاً إلى أن يضبط مسؤول الاستضافة `KANZ_FCM_SERVICE_ACCOUNT_FILE` خارج مجلد الويب. لا ترفع مفاتيح الخدمة إلى MStore/الوسائط ولا إلى ملف JSON العام ولا تلصقها في هذا snippet.
- الربط الآمن لإشعارات الطلبات الخاصة غير منفذ؛ لا ترسل بيانات عميل في موضوع عام.
- التحديث الإجباري يعتمد minimumBuild لكل منصة وenabled. لا تفعله لنسخة غير متاحة بالمتجر. يتطلب نسخة التطبيق الجديدة؛ لا يجعل النسخ القديمة التي لا تعرف هذا العقد قادرة على إجبار التحديث.
- سياسة الإعدادات المحفوظة تؤخذ عند البدء، ولا يوقف تحديث الصفحة الرئيسية عملية دفع جارية. السياسة البعيدة الجديدة تصبح فعالة في التشغيل البارد التالي بعد التخزين.
