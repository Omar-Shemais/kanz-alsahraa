### دفعة النقل المشفر وطلبات WooCommerce

- Android usesCleartextTraffic أصبح false؛ ATS في iOS لم يعد يجيز arbitrary loads أو arbitrary WebContent، دون استثناء نطاق HTTP أو إعداد debug يعيد فتح السماح العام. اختبارا XML يثبتان المصدر والـoverlays؛ XML 6.6.1 صار dev dependency مباشرة بنفس إصدار lock السابق.
- أُضيف SecureHttpClient لطلبات WooCommerceAPI GET/POST/PUT/stream وhttpCache وخدمة ملف الكاش. يمنع HTTP وuserinfo، ويوقف التحويل إلى HTTP، ويمنع انتقال الطلبات ذات اعتماد/جلسة إلى أصل آخر. تحويلات HTTPS العامة للـCDN تبقى ممكنة مع إسقاط headers، وتُفحص بيانات الاعتماد التي قد تُضاف في تحويل لاحق أيضاً.
- لا يُعاد إرسال POST/PUT تلقائياً بعد redirect؛ على الخادم توفير endpoint نهائي صحيح. أخطاء الاتصال وقراءة stream في هذه الطبقة لا تتضمن URL أو استجابة upstream. تُغلق موارد POST/PUT بعد القراءة؛ أُزيل تسجيل URL/endpoint والكاش المشتمل على query من المسارات المعدلة.
- أُزيل debugNetworkProxy الذي كان يجيز شهادة غير موثوقة على Android في WooCommerceAPI؛ ولا يعود getAsync يبتلع الخطأ ويعيد null. لا يُنشأ استثناء HTTP أو شهادة ذاتية للموقع الحي.
- أُضيفت 10 اختبارات عميل مشفر واختبارا إعدادات المنصتين. المجموعة النهائية كاملة نجحت: 79 اختباراً، وبناء Android debug النهائي بعد عميل HTTP نجح، وmanifest المدمج يؤكد usesCleartextTraffic=false. التحليل النهائي للملفات الستة: No issues found، بعد إصلاح ملاحظة braces في الاختبار. git diff --check للدفعة نظيف.
